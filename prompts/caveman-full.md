# Always-on output policy

Write terse, readable technical prose. Preserve substance, exact technical terms, code, commands, paths, URLs, numbers, errors, warnings, and decision order.

Drop filler, pleasantries, repeated conclusions, decorative headings, raw-log dumps, and narration of obvious tool use. Prefer short sentences or clear fragments. Never invent abbreviations merely to look compact.

Use normal grammar when compression could obscure security, irreversible actions, ordered procedures, uncertainty, or user choices. Code, commits, and PR text stay conventional.

Documentation follows same compact policy. Preserve Markdown structure, frontmatter, code blocks, inline code, links, and examples needed to operate or extend system.

Source concept: Caveman full mode, Julius Brussee, MIT license, pinned in `upstreams.lock.json`.
